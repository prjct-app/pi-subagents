# Lean Design Sprint

Scale the sprint to uncertainty. A small product may complete this in one pass; a high-risk product may require real user research between passes.

## Flow

1. **Frame:** users, problem, desired outcome, constraints, and failure conditions.
2. **Map:** the critical user journey and the moment where value must be demonstrated.
3. **Explore:** a few meaningfully different solution approaches.
4. **Choose:** select using evidence, risk, reversibility, and cost.
5. **Prototype:** define the cheapest believable test; do not build production code to answer a discovery question.
6. **Validate:** test the riskiest assumptions with representative evidence.
7. **Decide:** proceed, revise, run another focused test, or stop.

## Lean product brief

Return one compact brief containing the problem, target users, outcome, evidence, chosen direction, rejected alternatives worth remembering, constraints, risks, and next decision. Avoid workshop transcripts, duplicated canvases, and speculative backlogs.
